# 管理后台（Staging）

地址：https://staging.x-reply-helper.top/admin/

使用用户指定的首笔成功付款账户登录。唯一管理员绑定保存在 site_administrator 的稳定 user ID；role=admin 也受唯一索引限制，公开接口不能修改管理员身份。管理员继续正常使用插件及自身额度。

## 日常操作

- 用户：邮箱/ID 搜索、历史订单/生成/流水、免费或付费额度调整、单个或批量冻结/恢复。
- 所有写操作填写原因；确认后首次要求重新验证账户密码，证明有效15分钟。网络结果不明确时重试原操作，操作编号保持不变，避免重复增加额度。
- 套餐：创建/上下架、名称/介绍、美元展示价、固定人民币或手动汇率结算、服务费率和次数。旧订单价格/权益及结算快照不会更新。
- 网站内容：X主页、Chrome商店、客服邮箱、首页标题/公告/介绍、指南和FAQ。纯文本显示；不支持HTML。未填写商店或X链接时不会编造链接。
- 审计：操作ID、执行管理员、目标、原因和时间可追溯。
- 测试账号：先明确标记，再可恢复归档；有任何支付订单（包括UNKNOWN）的账户不能归档，可冻结，交易与审计不删除。

## 安全与范围

支付继续使用已验证的易支付；支付创建及Staging测试购买开关均关闭。Webhook保留开启，AI使用Mock。后台开关仅Staging开启，Production仍关闭。

部署包含0011增量迁移；不改旧迁移、不迁入Staging账户到Production。代码、认证安全策略、Secret、域名、D1迁移与新支付协议仍通过开发部署管理，后台不读取或编辑真实Secret。

## 发布与恢复

0011只添加元数据/列，原交易与余额不重算。出现后台问题先关闭Staging ADMIN_PORTAL_ENABLED并部署当前安全配置；不要回退数据库或删除流水。前端可恢复到发布前Staging Pages部署。旧Worker依赖先前字段仍兼容，但恢复时必须保持支付关闭与Invocation Logs关闭。

Production发布另行授权：先配置独立D1/域名/Secrets，按顺序执行迁移并备份，绑定正式管理员，核对正式易支付notify/return URL、Chrome商店链接与客服及法定条款。不要复制Staging测试数据。
