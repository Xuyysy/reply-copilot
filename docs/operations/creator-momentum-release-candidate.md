# Creator Momentum · 发布候选版验收清单

本指南适用于 `codex/creator-momentum-release-candidate-v1`。源代码提交并不等于已完成真实浏览器验收或生产部署。

## 目标和范围

- 保留原有 x-Reply-Helper Logo、普通悬浮窗 V2、风格选中、PRO 提醒和所有生成/ACK/填入/扣次业务逻辑。
- 移除侧边栏的「提醒效果测试 · Staging」与「Staging 匿名性能测量」用户可见入口和对应前端模块。
- 管理后台「互动势能运营控制台」按策略、文案、预览和历史组织。配置仍通过现有服务端读写与审计回滚接口保存。
- Staging 管理后台显示「填入低阈值验收区间」；仅填写未保存草稿，必须经过手动保存和操作确认；Production 不显示此快捷按钮。
- 不新增扩展权限、第三方 UI 运行时或 X 官方数据集成。Production 构建不包含 Staging 目录。

## 重要机制

- 三阶段范围需按顺序递增且互不重叠。可用于 Staging 的低阈值范围为 `[[1,2],[3,4],[5,6]]`，每日最多提醒 `3` 次。生产正式阈值不是此低值。
- 计数是此插件本机当日**成功生成且收到 ACK**的事件；不等于用户实际在 X 发送评论。
- 阈值从区间内选一个值，并在当天首次有效计数时固定整日策略。当天已开始计数的账号改变后台阈值后不会立即重算。使用当天尚未计数的隔离测试账号/全新本地状态，或在下一本地自然日验证；不能假装立即生效。
- 需有服务端验证的真实**已购买 PRO 资格**以及账号主动开启监测。仅有免费余额、测试按钮或模拟预览不代表真实购买权益。
- 满足阈值后，提醒在**下一次点击 X 原生「回复」**时、AI 生成之前出现。关闭/继续后，应在同一绑定编辑器恢复并最多生成、ACK、扣次、自动填入各一次；不得覆盖用户原草稿。
- 提醒文案及全局暂停在客户端重新获取权益后生效；并非实时 WebSocket 推送。已产生的今日免打扰不会被修改阈值清除。
- Staging 的低阈值也是**全局配置**，可能影响符合资格的全部 Staging 用户。用隔离的 Staging 账号与数据执行；测试后必须通过历史回滚或重新编辑恢复正常阈值。

## 上线前必须完成

1. 在持久化独立 Clone/worktree 中 fetch 本分支，先检查未提交内容；记录源 SHA。不要修改原 Creator Momentum 工作区。
2. 按锁文件 `npm ci` 安装根、web、api 实际需要的依赖，执行 `npm test` 并保存完整日志和退出码。不得只报部分通过。
3. Chrome 隔离 Profile 加载**实际 Staging 构建**，深色/浅色、320/375/常规宽度检查：侧边栏无测试卡片；原 Logo 不变；V2 仅一个风格高亮；六个设置分类和账户/PRO 正常。
4. 管理后台先在隔离 Chrome 完成：四个控制台分区、Staging 才显示低阈值预设、预设只是草稿、未经管理员确认无网络保存、预览没有 AI/真实提醒副作用、双语文案保存后重新读取、历史回滚与窄屏布局。测试真实服务端前应先获批准部署 **Staging Pages**；仅构建本地 Web 不能改变已部署的管理员界面。
5. 在 Staging 管理后台开启全局提醒并保存低阈值；验证 GET 版本、配置、客户端手动「刷新购买权益」。进行本机当日 2/4/6 次 ACK 触发保证达到三阶段上界，**每达到阶段后下一次点击原生回复检查**。不得通过人工篡改数据库/计数记录伪造通过。
6. 每一阶段点击继续后确认不丢编辑器上下文、不重复 AI 调用或扣次，关闭/今日免打扰表现正确；实测真实 X 页面时避免发布真实评论，使用隔离测试账号和额度。
7. 测试完成后恢复原策略区间并确认新版本。记录每阶段截图、请求次数、服务端审计记录、当天已有策略的边界与尚未覆盖的路径。
8. 再做模拟全链路延迟 P50/P90 与前一版比较，重点检查生成→ACK→安全填入，禁止因管理 UI 变更产生额外客户端请求。
9. 生成 Staging ZIP，计算 SHA-256、source SHA、manifest 版本、API、扩展身份及权限；原路径安全备份并给出安装命令。**不要直接替用户安装**。
10. 如需生产发布，另行核查 Web Store 原上架版本号、Production 构建 HTTPS origins、既有 Extension ID / 公钥、权限与隐私声明；只有获得明确授权后才部署 Worker/Pages、提交 Web Store 或变更线上后台配置。

## 报告格式

报告应列出：GitHub 分支和最新远端 SHA、所有更改文件、全量测试数/失败数/退出码、Chrome 截图、后台分区验收、三阶段真实触发/关闭恢复的逐阶段证据、性能对照、ZIP 绝对路径及哈希、安装命令、未验证项目。
