# 易支付异常：最小人工对账流程

适用现有小豆易支付。不启用旧 RSA2 查单，不凭页面回跳、截图或客户声明补发，不自动退款。

1. 管理员在订单页记录本地订单号、out_trade_no、预期总额/币种、权益数量、通知处理情况；建立私有客服工单，勿粘贴 Key/签名/收银链接。
2. 登录小豆官方商户后台，按**同一个商户**和 out_trade_no 查询，核对支付平台交易号、实付金额和最终成功状态。没有最终成功证据或金额冲突：继续“待核对”，联系平台支持，勿判成功/重下单。
3. 若确已支付但本地尚未入账：使用商户后台的原通知重发能力；如后台没有该按钮，请平台支持重投**原始官方通知**，不用我方合成签名回调。上线前由经营者确认该支持渠道可用及处理时限。
4. 我方现有 notify GET 验证 MD5、PID、订单归属、金额和 TRADE_SUCCESS，原子写支付状态、400/1000/2000次批次、purchase_grant；同一订单重复通知只到账一次。关闭购买不关闭通知。
5. 只读执行 api/sql/payment-consistency-audit.sql，所有 anomalies 应0；核对 paid、credited_at、唯一批次、唯一购买流水和账户余额。用户重新进入/聚焦账户页会读取本地可信状态及新余额。
6. 记录工单处理人、时间、平台证据来源/交易号（私有保存）、通知重投结果、我方核验结果并关闭工单。保留历史 UNKNOWN；无证据不改其状态。

如果平台无法提供可信通知重投：**暂停该订单人工补发并升级平台支持**。不能用后台“赠送额度”冒充支付补单，否则订单、购买批次和财务将不一致。该情况是上线运营阻断项，应先确认重投支持，或以后取得完整官方查单信任合同后再做最小适配，不猜 api.php 字段。

用户等待文案：“付款结果正在核对，请勿重复支付。请提供本网站订单号；我们会通过支付平台核实，截图不作为自动到账依据。”

停止损失：后台关闭新购买，保留通知/旧订单读取和原凭证；不删除订单，不换号退款，不手工改余额。退款/争议由经营者按适用法律和支付渠道办理，本轮不新增退款功能。


## 官方资料已核实的重投范围（2026-10-22）

本机官方文档 `13-epay-compat-integration.md`，docId XD-OP-13/version1.0.0，§2.4明确：异步GET通知需纯文本success；否则退避重投，首次即时、之后分钟到小时级，最多8次。这证明**自动重投**存在，不证明商户后台一定有“手动重发”按钮。

当前资料没有描述手动重发按钮或可调用的通知重投API，也没有完整定义api.php返回的签名/可信字段合同。因此本轮没有调用平台API、伪造通知或凭截图补发。运营者仍须在小豆后台确认手动重发入口，或取得平台客服的原通知重投处理方式及响应时限；在此之前将漏通知工单标为待平台核验，不用普通赠额替代财务入账。
