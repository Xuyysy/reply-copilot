Sources inspected (for architecture, not copied):
- https://github.com/Christian-von-Uffel/x-feed-analyzer/blob/main/content.js — author-bearing `div[role=link]` quote cards, separate main tweet text/ID. No LICENSE file found; no source code copied.
- https://github.com/nirholas/XActions/blob/main/src/timelineScraper.js — multiple quote DOM shapes and stable data-testid selectors; Apache 2.0.
- https://github.com/zendegani/XClipper/blob/main/src/content/dom-to-ast/quote.ts — independent quote node model; **PolyForm Noncommercial** and excluded from all code reuse.

User reports prior `[data-testid=quoteTweet]`-only Staging fix did not work. Code inspection shows an erroneous second-outer-text requirement that breaks quote-only role=link cards and sometimes confuses outer with quoted status ID. This experiment adds role=link boundaries only when the card has an author and tweetText and another outer timestamp exists. The modal binds only on verified outer status ID **plus** matching quoted preview for quote-only posts. Ambiguous cases still fail closed.

No extra network/model calls, no new timers, no new DOM mutation on successful regular posts. Local-only text-free diagnostics: open Chrome devtools in x-Reply-Helper isolated script context after a failed click and evaluate `replyCopilotAssociationReport()`; it returns stage/reason/timing only, no post content or usernames. A real failing quoted-post URL/DOM remains needed for definitive validation.

## 2026-11-14 reported X quote reply issue (Staging follow-up)

Public report: https://x.com/pigeontwting/status/2121135421413613951 . Real user's local diagnostic gave two `activated/trusted_reply_click` → `rejected/reply_context_unconfirmed` sequences within approximately 189–213 ms. Thus source capture worked, but modal binding failed. The public X page DOM was inaccessible from this environment, so the fix is a code-based hypothesis, not real-X verification.

Modal parent discovery now excludes both marked cards and author-bearing `div[role=link]` quote descendants (article and bare tweetText). Quote-only modal hydration waits until a verified outer parent appears rather than binding on quote text alone or prematurely rejecting. When the modal's OUTER canonical parent ID uniquely matches, a temporarily absent quoted preview is no longer a veto; an explicitly different quoted preview remains a failure. Failed context matches now record a text-free `context_detail` reason. No new model calls, telemetry, database or Production changes. Do not merge until human verified on the linked X post.

## 2026-11-15 real browser evidence — quote copy-only fallback

User report from the correct extension isolated world: `activated/trusted_reply_click`, `capture_kind/own_text`, `context_wait/awaiting_captioned_quote_parent`, then `rejected/association_expired` after nine seconds. `sourceFound=false` was measured after opening the dialog and can mean the feed article was removed by React, not missing original click capture. This experiment does **not loosen the automatic editor association**. When a trusted Reply gesture has captured a real quote, and after an 800ms grace exactly one **new focused empty** modal editor is present without an explicit parent identity, conflicting status ID, preexisting modal, stale activation, or route change, the plugin shows the existing floating UI in **manual copy-only mode**. AI generation requires the user's direct Generate click, never auto-generates or auto-fills, and never relies on an unverified editor as the text insertion target. The user can copy manually or open the sidepanel. Normal posts and verified bindings retain unchanged behavior. Do not merge/deploy/Chrome-Store until real X acceptance.

## 2026-11-15 user-requested automatic generation AND insertion (Staging-only)
The user explicitly rejected PR #133 because it continued to show manual generation and manual confirmation. Their acceptance target is a true automatic loop from trusted Reply click on the quote to AI generation and a single automatic native-editor insertion, without auto-posting.

For the PR #132 verified real-X fallthrough, the only fresh focused empty modal editor is already captured and the source is verified on the real trusted click, though X omits its repeated source identity in the hydrated modal. Under the existing strict baseline (no prior modal, no previous editor, exact one candidate, no explicit wrong parent ID, no route change, no input, no quarantine), if the user's existing `autoGenerateOnReply` preference is on and no quota/momentum gate is pending, this Staging experiment automatically starts ONE request and attempts ONE native paste into the SAME retained editor after full revalidation. The independent, fully verified normal reply path is unchanged. The manual mode survives for auto-off or safety-gated cases, and failed automatic insertion can fall back to copy/manual review.

No endpoint changes, no auto-publication, no remote DB operations, and no Production rollout before the actual quoted post and wrong-target cases are manually checked. A unique focus-linked editor is causal evidence, **not the same as a cryptographically verified reply-to identity**; this is explicitly a higher-risk Staging-only experiment needing review.
