## Minimal behavior change
The existing account button reads the authenticated order detail for its actual packageId and checks the existing active package list/valid CNY price, then opens `/checkout/?package=<packageId>`. It sends no original transaction query, attempts, cashier open or order-create request; it does not reset remembered payment tracking. Closed MK99 rows no longer have the special contact-support link. Global support, other order actions and dismissible payment events remain intact.

An explicit package query continues to override rememberedPayment. Normal checkout shows the current package price, original payment choices and existing pay button. The added order ID, recovery warnings, support/replacement blocks are removed. Existing explicit old order/return URLs still use the original checkout's status handling for compatibility; they are not the account continuation destination. The user must explicitly click the existing pay button to create a new order. Successful newly created orders keep their own original cashier safety checks and tracking.

The atomic recharge_orders INSERT guard gains only `package_id=?` inside the existing user/merchant/protocol unresolved predicate. It still blocks same-package pending/unknown orders across MK99 channels, does not infer closure from navigation or network failure, and does not modify old orders. Trusted closed state allows a fresh same-package order. Existing Epay explicit behavior is preserved. Different packages have distinct order IDs, transaction IDs, provider trade IDs, amount snapshots and purchase grants. All settlement, callback verification and financial batches are unchanged.
