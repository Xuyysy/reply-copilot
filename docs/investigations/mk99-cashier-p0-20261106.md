## Confirmed frontend regression, not a confirmed unique platform-error cause
Commit `264db11a17a277be1e9bddd5105586d7d8d37b5c` changed the normal MK99 cashier click from native noreferrer navigation to preventDefault + asynchronous status check + location.assign. The link markup kept its security attributes, but location.assign does not inherit them. The deployed page's Referrer-Policy is strict-origin-when-cross-origin, unchanged from the historical header file.

Isolated real Chrome network interception (only synthetic HTTPS domains, no merchant requests) measured:
- native noreferrer control: no Referer;
- current location.assign: Referer equals the source origin;
- candidate native verified-link navigation: no Referer; destination URL unchanged.
This establishes a browser-navigation regression and a plausible input to a domain check. It does NOT establish that MK99 checks this header, that missing Referer is permitted, or that a merchant/domain/gateway is approved. There is no real MK99 A/B, payment or order creation in this task.
