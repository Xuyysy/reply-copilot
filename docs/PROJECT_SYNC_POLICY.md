# Reply Copilot / x-Reply-Helper｜跨聊天同步与外部平台协作约定

> 用户于 2026-10-30 明确要求：后续 Reply Copilot 工作需要持续维护 Notion 与 GitHub 项目状态，并允许在适当任务中通过已连接的 Cloudflare、Resend 等插件读取项目真实情况。本文件记录协作规则，不代表已自动部署或建立后台监控。

## 项目范围与权威来源

- 此聊天及其跨聊天交接只围绕 **Reply Copilot / x-Reply-Helper**，不混入 X 账号运营、Auto Poster 或缪子科研。
- **GitHub**：实际源代码、分支、commit、PR、测试证据及发布产物对应关系。
- **Notion**：[项目进度总控](https://app.notion.com/p/402c089052a381869bf0d82015011e10) 与 [跨聊天交接手册](https://app.notion.com/p/404c089052a381f1a802ce1db2719454) 记录最新用户决定、状态、阻断项、风险和下一步。
- **Cloudflare**：在相关任务中以只读方式核实 Production / Staging Worker、Pages、D1 migration、必要的脱敏聚合数据及部署配置。
- **Resend**：在相关任务中以只读方式核实发信域名状态、投递与错误记录、相关服务配置；不读取或传播不必要的私人邮件内容。
- 若历史文档与新的已验证证据冲突，按**时间、证据类型和实际环境**厘清，不以旧“下一步”覆盖最新用户决定。

## 工作开始时

1. 任务涉及项目现状、代码、部署或外部邮件服务时，按需要重新读取对应真实来源；不要把旧交接内容当作实时状态。
2. 先辨别本次任务是需求分析 / 只读审计 / 为 Codex 提供实施指令 / 经用户授权的写入。
3. 若发现 GitHub 代码与 Cloudflare 实际部署不一致，明确分别标注“已推送源码”“已部署环境”“用户人工验收”“待证实”，不能相互推定。

## 工作结束时的同步要求

- **发生实质性产品决定、验收、修复、分支/部署状态变化时**：同步更新 Notion 进度总控和必要的跨聊天交接页；根据实际 GitHub 变更及用户授权更新对应发布/交接文档，保留准确链接、提交 SHA、版本、时间、验证结果和未解决风险。
- **仅讨论、推测或只读检查且状态无变更时**：无需制造无意义的提交；如发现新的风险或更正历史误报，可以记录到项目总控，并标明证据边界。
- 文档同步不能篡改历史事实、掩盖失败或把 Codex 自报测试当作助手独立执行的测试。
- 更新状态应告知用户哪些资料实际已改、哪些尚未改；不可声称自动双向实时同步。

## 写入与安全边界

- 用户允许访问已连接的 Notion / GitHub / Cloudflare / Resend 作为项目工作依据。默认读取；文档性同步仅限用户明确的合作范围。
- 未经用户明确授权，**不得**改变 Production/Staging 部署、D1 业务或财务数据、支付开关、活跃 AI 模型、DNS、Secrets、Resend 发信设置，也不得下单、支付、退款、发送真实邮件或更改 Chrome Web Store 发布。
- 对破坏性操作、正式上线、成本变化或外发邮件，必须分别得到明确批准；不得把“允许连接插件”理解为对所有写入的授权。
- 不在聊天、Notion、GitHub、日志或工具输出中暴露 API Key、Token、Cookie、密码、私钥、完整敏感数据。
- 这些规则仅在用户发起对话或显式创建的自动化运行时执行；**没有后台持续同步或自动监听**。
