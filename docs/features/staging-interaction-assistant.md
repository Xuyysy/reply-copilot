# Staging interaction assistant / P0 evidence pilot

User-initiated read of already loaded X notifications; no auto-scroll, API calls, page-world interception, new permissions, cookies, remote database or model calls. Only Staging packaging exposes this feature. Current snapshot counts visible identified actor/action rows (not full event history). Session confirmed mode deduplicates only rows with an explicit post identity; no persistence, no inferred actors or unknown timestamps, and handle-only identity is provisional (account rename/reuse cannot be established). Open notification page, click the panel button, manually scroll, click again. Switch tabs/account or close panel to end the session; changing owner/tab on the next successful read resets accumulated data. Unsupported locale/layout, hidden/aggregated actors, missing reply context and unavailable post links may reduce coverage. No guarantee of 7/30/90 days. No outbound, quotes, mentions or official archive import in this pilot.

Gate: real Chrome old/new X notification fixtures, known user/event comparison, empty and aggregated cases, account switching, no background requests and no regression in existing reply speed. If DOM evidence is insufficient, improve only using redacted actual fixtures and authorized data sources. Review X and Chrome store policy before any distribution. Production packaging must remain unchanged.
