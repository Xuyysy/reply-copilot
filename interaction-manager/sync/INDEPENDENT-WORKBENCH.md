# Independent workbenches (Staging candidate)
Two sidebar buttons open separate extension tabs. No business controls remain in the side panel. A session-scoped binding associates the workbench with an existing signed-in X tab, and the existing local identity check can be used read-only from ordinary X pages. This does not navigate X or issue remote requests. It is local evidence, not independent server attestation. The interaction page automatically reads the actual owner-scoped cache via the service worker; the follow page mounts the isolated authorized-cache module, not its fixture database. Both are empty when there are no real records. The provider factory is deliberately unconfigured: there is no verified, approved tab-independent transport yet. The worker has a bounded, transport-neutral task entry and uses existing atomic checkpoints if a provider is supplied, but no automatic network scheduling, and worker interruption recovery remains a provider integration task. No additional manifest permissions or production changes. The legacy pilot UI is retained only as a regression fixture, not an entry point.

Task lifecycle update: session-scoped status records mark orphaned running jobs as interrupted after service worker restart. Refresh resumes an unfinished checkpoint or starts a deduplicated new scan after an exhausted checkpoint, when a provider exists. A provider is still deliberately not configured. Local cache reads do not compete with active writes. UI polls while busy and retains same-owner cached results, but must hide them if identity changes. No alarms, remote calls, or permission changes.
