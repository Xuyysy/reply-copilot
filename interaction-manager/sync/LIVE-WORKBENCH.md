# Live interaction analysis
The side panel displays actual locally synchronized records (not the separate offline import DB). A single read transaction returns the current account's events, users, sanitized coverage and checkpoint summary; raw cursors never reach the view. The read-only cache/clear/export mode validates local signed-in identity without locating or requesting an endpoint. The current notification page is still required. All recorded users can be paged, filtered by interaction type/date, sorted, searched, inspected and exported locally. Unknown action dates are excluded from dated views; reply/quote suppress duplicate mention evidence. The default is inbound count. A 50k event storage limit applies transactionally to live checkpoint commits. No new request types, permissions, cloud writes or production changes. Browser/SPA identity revalidation remains necessary in real X; this is not independent server attestation.

Joint delivery hardening: the retained view uses an existing read-only local identity session, rechecked before local filtering, paging, details and export, and while visible every 1.5 seconds. It issues no X requests. Clear invalidates the displayed session; late start replies are cancelled if the task was stopped. Errors are mapped to bounded user-facing status codes. Checkpoint transactions retain per-scan observed skip/unresolved/foreign-target counts with the number of pages carrying those diagnostics; they are not unique missing events or estimates of total history. Old checkpoints may have no diagnostics. The actual X response coverage and identity evidence still require local validation.
